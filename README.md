# VACON — AI 기반 팀 휴가 및 업무 연속성 관리 비서

팀원의 휴가 일정과 업무 정보를 분석해 **업무 공백을 사전에 예측(Prediction)**하고,
**대체 담당자를 추천(Recommendation)**하며, **인수인계 문서를 자동 생성(Automation)**하는 Streamlit 앱입니다.
외부 API 키·유료 서비스 없이 규칙 기반으로 모든 핵심 기능이 동작합니다.

## 설치 및 실행

Python 3.10+ 필요.

```bash
cd vacon
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

브라우저에서 http://localhost:8501 이 열립니다. 첫 실행 시 `data/vacon.db`(SQLite)가 만들어지고
가상 샘플 데이터(팀원 9명·업무 13개·휴가 8건)가 자동 입력됩니다. 샘플 날짜는 **실행 시점의 이번 주 월요일 기준**이라
언제 실행해도 시연이 가능합니다.

| 환경변수 | 설명 |
|---|---|
| `VACON_DB` | DB 파일 경로 변경(기본 `data/vacon.db`) |
| `VACON_TODAY` | 오늘 날짜 고정(YYYY-MM-DD). 시연·재현용 |
| `ANTHROPIC_API_KEY` | (선택) 설정 + `pip install anthropic` 시 AI 비서가 규칙 기반 결과를 자연어로 요약 |
| `VACON_LLM_MODEL` | (선택) LLM 모델명 변경 |

### 위험도 판단 방식 (`services/risk.py`, `services/config.py`)
담당자가 부재인 날을 기준으로 가중치를 합산합니다(데이터 관리 > 위험 규칙에서 변경 가능).

`담당자 부재 30 + 중요도(상 20/중 10) + 대체자 미지정 25 또는 대체자도 부재 25 + 마감 임박(3일 이내) 20 + 역량 보유 근무자 없음 20 + 팀 가용 인원 50% 미만 10`
→ 점수 ≥ 75 **High**, ≥ 40 **Medium**, 그 외 **Low**.
담당자·중요도가 비어 있으면 안전하다고 단정하지 않고 **데이터 부족**으로 표시합니다. 위험도는 **근무일(월~금)** 기준입니다.

### AI 비서 지원 질문
- "다음 주에 업무 공백 위험이 높은 날짜는?"
- "휴가 중인 핵심 담당자가 누구야?" (핵심 담당자 = 중요도 '상'인 미완료 업무의 담당자)
- "대체 담당자가 지정되지 않은 업무를 알려줘."
- "이번 주 휴가 인수인계 문서를 만들어줘."
- 그 외: "오늘 부재 인원은?", "이번 주 위험도가 높은 업무 목록"

기간 표현은 오늘/내일/이번 주/다음 주/이번 달/다음 달을 인식합니다. 지원하지 않는 질문은 추측하지 않고 안내합니다.

### 메일 요약 (`services/mail_digest.py`)
메일 서버에는 연결하지 않으며 사용자가 가져온 메일만 처리합니다(저장하지 않고 세션 메모리에만 유지).
- 입력: `.eml` 여러 개 / CSV(`받은날짜,보낸사람,제목,본문`) / `보낸사람: · 받은날짜: · 제목:` 형식 붙여넣기 / 샘플 메일
- 처리: 선택한 기간 안의 메일만 요약(기간 밖·날짜 없는 메일은 따로 표시) → 긴급/요청/공지 키워드, 본문 내 기한 날짜, 업무명 매칭(2개 이상 일치 시 '추정')으로 우선순위 판단
- 모든 항목에 판단 근거를 표시하며, 규칙 기반 요약이므로 중요한 메일은 원문 확인이 필요합니다.
- (선택) `ANTHROPIC_API_KEY` 설정 시 "AI로 브리핑 다듬기" 체크박스가 나타나며, 체크한 경우에만 메일 제목·요약이 외부 API로 전송됩니다.

### 구글 시트 연동 (데이터 관리 > 시트 연동)
탭별 CSV(`/export?format=csv&gid=…`)를 읽어 업무·마감일을 갱신합니다. 열 이름을 코드에 고정하지 않고 **화면에서 열 매핑**을 지정·저장합니다.
1. 시트 공유를 "링크가 있는 모든 사용자 - 뷰어"로 설정하고 주소를 저장합니다.
2. 탭을 추가합니다: 탭 이름, **gid**(해당 탭을 열었을 때 주소 끝 `#gid=` 뒤 숫자), 역할(업무 목록/일정), 헤더 행 번호.
3. "열 목록 불러오기" → 업무명·담당자·상태·진행률·마감일 등을 드롭다운으로 매핑 → 저장.
4. "시트에서 새로고침(미리보기)" → 추가/변경/사라짐 건수와 변경 내용을 확인 → "반영".
- 시트 값이 원천인 항목(담당자·상태·진행률·마감일·남은 작업·주의사항)만 갱신합니다. **대체 담당자·중요도·예상 부담은 덮어쓰지 않습니다.**
- 시트의 빈 칸은 기존 값을 지우지 않으며, 해석할 수 없는 값(상태·날짜·진행률)은 추측하지 않고 경고로 표시하고 건너뜁니다.
- 시트에서 사라진 업무는 자동 삭제하지 않고 목록으로만 알려줍니다.
- 시트의 열 이름이 바뀌어 매핑이 깨지면 반영하지 않고 알려줍니다. 업무는 업무명(공백·대소문자 무시)으로 식별하므로 시트에서 이름을 바꾸면 새 업무로 보입니다.
- 직접 연결이 막힌 환경에서는 탭을 CSV로 내려받아 같은 화면에서 업로드하면 동일하게 처리됩니다.
- 새 업무의 필수 역량·기본 중요도는 탭 설정에서 지정합니다(중요도를 '미입력'으로 두면 위험도가 '데이터 부족'으로 표시되어 입력을 유도).

### 버전 데이터 경로
- T0800 미만의 숫자형 T 버전은 기존 Google Sheets 로그로 조회합니다. T0800 이상은 VACON 내부 DB에서 관리하며 시트 동기화 시 해당 행만 제외합니다.
- 내부 버전은 `version_projects`와 서브시스템별 물량 테이블을 사용합니다. 요구사양서 작성 기록(`spec_work_logs`)과 동적 검증 기록(`version_dynamic_work_logs`)은 서로 다른 테이블에 저장됩니다. 기존 Sheets 연동의 `req_work_logs`/`dynamic_work_logs` 테이블은 그대로 보존합니다.
- `업무 계획 및 일정 관리`에서 버전과 마감일, 서브시스템별 목표를 등록합니다. 담당자 실적은 `업무 실적 등록`에서 기록하고 업무 로그에서 통합 조회합니다.
- 담당자 배분은 등록된 현재 업무량, 휴가, 역량, 난이도와 내부 버전 처리 이력을 기준으로 추천합니다. 처리 이력이 없으면 마감 가능성을 단정하지 않습니다. 추천은 PM 승인 버튼을 눌러야 배정으로 저장되며 LLM 설명은 별도 동의가 있을 때만 팀원명·배정 요약을 Anthropic API로 전송합니다.

### 단위 테스트 업무 로그 (📈 업무 로그, 데이터 관리 > 시트 연동)
단위 테스트 인원(`단위테스트` 역량 보유자: 주해원·김재강·황지원·이혜윤)의 두 업무 — **동적 검증**, **요구사양서 작성** — 의 일일 업무 로그를 시트에서 가져와 분석합니다.
- **열 지정(열 문자 기준, 기본값 설정됨):** 동적 검증(`2. Dynamic_Verification`) = 날짜 A · 담당자 B · 버전 C · 업무 구분 D · 완료 Req I · 완료 Func L · 실행 TC O / 요구사양서 작성(`3. Req_Creation_WBS`) = 날짜 A · 담당자 B · 버전 C · 업무 구분 D · 완료 일감 G. 서브시스템은 헤더명으로 열을 제안하며, 탭마다 **gid**만 입력하면 됩니다.
- **해석 규칙(가정):** 시트 한 행 = 한 사람의 하루 기록(같은 날 여러 행은 합산), 숫자 칸은 그날의 건수입니다. 숫자가 아닌 텍스트 칸은 쉼표·줄바꿈 기준 항목 개수로 세고 미리보기에서 알려줍니다. 해석할 수 없는 날짜·이름의 행은 건너뛰고 사유를 표시합니다.
- **날짜 형식:** `2026-10-19`, `2026. 10. 19.`, `2026년 10월 19일`, `26.10.19`, `10/19/2026`, `20261019`, 요일·시간이 붙은 값(`10/19(월)`, `2026-10-19 09:30`), 시트 일련번호, 연도가 없는 `10/19`·`10월 19일`을 읽습니다. 연도가 없으면 오늘 기준 가장 가까운 과거로 추정하며(탭 설정에서 연도 직접 지정 가능), 읽지 못한 값은 **예시와 함께 화면에 표시**합니다.
- **진단 도구:** "열 목록 불러오기"를 누르면 앱이 실제로 읽은 시트 상단(행 번호·열 문자 포함)을 보여주고, 제목 행이 다른 위치에 있으면 행 번호를 추정해 알려줍니다. 날짜·담당자가 병합 셀이면 "병합 셀 대응"을 켜세요.
- **시트 구조 변경 감지:** 저장한 열 제목과 현재 시트의 해당 열 제목이 다르면 반영하지 않고 알립니다. 반영은 미리보기(팀원별 합계) 확인 후 **탭 단위로 교체**(누적 아님)되므로 시트에서 수정·삭제한 내용도 그대로 따라갑니다.
- **집계 기준:** 최신 버전이 위에 오도록 정렬하며 버전과 서브시스템을 선택합니다. 선택한 버전의 전체 로그 또는 해당 서브시스템 로그만 집계합니다. 서브시스템 열이 매핑되지 않은 과거 로그는 `서브시스템 미입력`으로 분류됩니다.
- **분석:** 팀원·업무별 처리량(근무일 기준 일평균, 주말·종일 휴가 제외; 로그가 없으면 0이 아니라 '-'), **휴가 영향 예측**(최근 일평균 × 휴가 근무일 = 예상 처리 공백, 나머지 단위 테스트 인원이 처리량 비례로 나눠 맡을 때의 추가 부담과 '평소 대비 +n%'), 단위 테스트 인력 가용 현황.
- **단위 테스트 인원 전용 규칙:** 필수 역량에 `단위테스트`가 들어간 업무는 담당자·대체 담당자가 단위 테스트 인원이어야 합니다(입력 화면·시트 동기화에서 검증). 대체 담당자 추천은 필수 역량을 **모두** 가진 사람만 후보로 올립니다(필수 역량은 쉼표로 여러 개 지정: `단위테스트, 요구사양서 작성`). 위험 분석에는 '역량 보유자 다수 부재' 항목이 추가되었습니다.
- 인수인계 문서(단위 테스트 인원)에 최근 14일 로그 요약과 휴가 중 예상 처리 공백이 포함되고, AI 비서가 처리량·처리 공백 질문에 답합니다.
- 예측은 과거 평균에 근거한 참고값이며, 마감 달성 가능 여부는 남은 물량(전체 Req/TC 등) 정보가 있어야 판단할 수 있습니다.

### 버전별 동적검증 (🧪 버전별 동적검증)
- 사양서 작성 단계와 동적검증 단계를 각각 등록·수정하며, 두 단계는 같은 버전명으로 연결됩니다. 전체 사양서 수는 요구사항 수, 전체 검증 대상 수는 서브 펑션 수로 입력합니다.
- 요구사양서 진행은 요구사양서 시트의 `사양서 작성` 구분 행에서 완료 일감(G열)을 집계합니다. 동적검증 진행은 동적검증 시트의 완료 Func(L열)로 집계하고, 완료 Req(I열)와 TC 실행(O열)은 동적검증 기록으로만 관리합니다.
- 각 단계의 팀 일일 권장량은 `ceil(남은 수량 / 남은 팀 업무일)`입니다. 오늘부터 마감일까지의 평일에서 담당자 휴가를 반영합니다. 회사 휴일은 제외하지 않습니다. 종일 휴가는 0일·반차는 0.5일로 반영합니다. 담당자 미지정 시 휴가를 반영하지 않은 참고치로 표시합니다.
- 사양서 처리 상한은 선택 입력입니다. 동적검증 일일 최대 처리량은 입력받지 않으며, 남은 Func 수와 남은 업무 가능일로 권장량을 계산합니다. 대체 담당자를 자동 배정하거나 마감일을 자동 변경하지 않습니다.
- 일정, 담당자, 진행 수, 휴일 등 버전 정보 변경 이력을 저장합니다. 데이터베이스에는 기존 데이터를 유지한 채 `version_projects`, `version_history` 테이블을 추가합니다.
- 시트 연동은 현재 CSV 형식(구글 시트 CSV 내보내기 또는 CSV 업로드)을 지원합니다. 헤더 행 번호는 파일의 첫 행을 1로 계산하며, 상단 미리보기와 추정 후보를 확인한 뒤 사용자가 적용합니다. XLSX 파일은 이 연동 화면에서 지원하지 않습니다.

### AI Agent (💬 AI 비서)
- 기존 규칙 기반 비서는 API 키 없이 계속 동작합니다. 복합 질의는 화면에서 **다단계 AI Agent 사용**을 켜면 Anthropic Messages API의 client-side Tool Use로 필요한 VACON 조회를 최대 6회 순서대로 수행합니다.
- 도구는 휴가 조회, 버전/진행률 조회, 업무량 계산, 위험 분석, 대체 담당자 추천, 인수인계 초안 생성입니다. 기존 DB·서비스 함수를 사용하며 SQL/Python 임의 실행과 데이터 변경 도구는 제공하지 않습니다. 추천 지정, 휴가 변경, 일정 변경, 문서 저장/전송은 Agent가 실행하지 않습니다.
- Agent는 업무 질문과 도구가 반환한 해당 업무의 데이터만 Anthropic API에 전송합니다. 사용자가 화면에서 Agent 사용을 직접 켜야 합니다. 실행 기록에는 도구명·성공 여부·소요 시간만 남습니다.
- 사용하려면 `pip install "anthropic>=0.40"` 후 `ANTHROPIC_API_KEY`를 환경 변수로 설정하세요. API 키가 없거나 API 호출이 실패하면 기존 규칙 기반 답변을 사용합니다. 사용 모델은 `VACON_LLM_MODEL`로 바꿀 수 있습니다(기본 `claude-sonnet-4-6`).

## 구조

```
app.py            진입점(좌측 사이드바 세로 메뉴)
views/            페이지별 UI (Streamlit은 `pages/` 폴더를 자동 멀티페이지로 인식하므로 `views/` 사용)

data/             db.py(SQLite 접근), sample_data.py

```

## 제한 사항
- 기존 위험 분석·휴가 영향 예측은 회사 공휴일을 관리하지 않으며 주말만 제외합니다. 버전별 업무량 추천도 주말과 담당자 휴가를 반영합니다.
- 반차는 기본적으로 '부재'로 보지 않고 가용 인원에서 0.5명으로만 계산합니다(규칙에서 변경 가능).
- 업무량·예상 업무 부담은 사용자가 입력한 값을 그대로 사용하며 실제 업무 시스템과 연동하지 않습니다.
- 사용자 인증/권한, 다중 사용자 동시 편집은 지원하지 않습니다(로컬 SQLite 단일 사용자 기준).
- 구글 시트 연동은 앱에서 '새로고침'을 누를 때 읽어 오는 방식이며 실시간 자동 반영은 아닙니다. 공유 설정이 막힌 시트는 CSV 업로드를 사용합니다.
- 메일은 자동 수집하지 않습니다(Outlook/Gmail 연동 없음). 메일 요약은 키워드 기반이라 뉘앙스·문맥을 놓칠 수 있습니다.
- MBTI는 팀원 정보로 저장·표시만 하며 위험도 계산이나 대체 담당자 추천에는 사용하지 않습니다.
- 기존 `vacon.db`는 실행 시 `mbti` 컬럼이 자동 추가되어 데이터가 유지됩니다.
- LLM 요약은 선택 기능이며, 규칙 기반 답변을 문장으로 다듬는 용도로만 사용합니다.
