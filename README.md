# VACON — AI 기반 팀 휴가 및 업무 연속성 관리 비서

팀원의 휴가 일정과 업무 정보를 분석해 **업무 공백을 사전에 예측(Prediction)**하고,
**대체 담당자를 추천(Recommendation)**하며, **인수인계 문서를 자동 생성(Automation)**하는 Streamlit 앱입니다.
기본 업무 계산은 VACON 내부 규칙과 데이터로 동작하고, AI 비서는 사내 ALIRA 서버를 사용합니다.

## 설치 및 실행

Python 3.10+ 필요.

```bash
cd vacon
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

브라우저에서 http://localhost:8501 이 열립니다. 첫 실행 시 `data/vacon.db`(SQLite)가 만들어지고
가상 샘플 데이터(팀원 9명·업무 13개·휴가 8건)가 자동 입력됩니다. 샘플 날짜는 **실행 시점의 이번 주 월요일 기준**이라
언제 실행해도 시연이 가능합니다.

| 환경변수 | 설명 |
|---|---|
| `VACON_DB` | DB 파일 경로 변경(기본 `data/vacon.db`) |
| `VACON_TODAY` | 오늘 날짜 고정(YYYY-MM-DD). 시연·재현용 |
| `ALIRA_API_BASE` | (선택) 사내 OpenAI 호환 LLM 추론 서버 주소(예: `http://10.10.10.200:19640/v1`). `ALIRA_MODEL`과 함께 설정 시 AI 기능 사용 |
| `ALIRA_MODEL` | (선택) 모델 ID(예: `Qwen/Qwen3.6-27B`, 서버의 `GET /v1/models` 값). `VACON_LLM_MODEL`도 인식 |
| `ALIRA_API_KEY` | (선택) 서버가 인증을 요구할 때만 Bearer 토큰으로 전송 |
| `VACON_LLM_THINKING` | (선택) `1`이면 Qwen thinking 모드 사용. 기본은 꺼짐(응답 속도 우선) |

### 위험도 판단 방식 (`services/risk.py`, `services/config.py`)
담당자가 부재인 날을 기준으로 기본 위험 가중치를 합산합니다.

`담당자 부재 30 + 중요도(상 20/중 10) + 대체자 미지정 25 또는 대체자도 부재 25 + 마감 임박(3일 이내) 20 + 역량 보유 근무자 없음 20 + 팀 가용 인원 50% 미만 10`
→ 점수 ≥ 75 **High**, ≥ 40 **Medium**, 그 외 **Low**.
담당자·중요도가 비어 있으면 안전하다고 단정하지 않고 **데이터 부족**으로 표시합니다. 위험도는 **근무일(월~금)** 기준입니다.

### AI 비서
질문 유형에 제한을 두지 않고 모든 질문을 ALIRA에 전달합니다. VACON 데이터가 필요한 질문은 ALIRA가 읽기 전용 조회 도구를 선택해 확인합니다. 설정이 없거나 API 호출이 실패하면 규칙 기반 안내로 답을 꾸며내지 않고 ALIRA 연결 오류를 표시합니다.

### 메일 요약 (`services/imap_mail.py`, `services/mail_digest.py`, `services/mail_ai.py`)
회사 메일 서버(`gw.suresofttech.com:993`, IMAP over SSL)에 **읽기 전용**으로 접속해 대상 기간에 받은 메일을 가져옵니다. 표준 라이브러리 `imaplib`만 사용합니다.
- 메일 요약 화면에서 **대상 기간**, 메일 주소(Outlook IMAP 설정의 사용자 이름과 같음, 아이디만 넣으면 `@suresofttech.com`을 붙임)와 그룹웨어 비밀번호를 입력합니다. **메일 서버 로그인 확인**으로 로그인과 받은메일함 접근을 확인할 수 있습니다.
- 받은메일함을 `EXAMINE`(읽기 전용)으로 열고 `BODY.PEEK`로 읽으므로 메일의 **읽음 상태가 바뀌지 않습니다**.
- 서버 검색(`SINCE`/`BEFORE`)으로 기간 메일만 받고, 수신일은 메일 헤더 `Date`를 이 PC 시간대로 바꿔 판단합니다(없으면 서버 수신 시각). 최신순 최대 500건까지 가져옵니다.
- 서버 주소는 환경변수 `VACON_IMAP_HOST`, `VACON_IMAP_PORT`, `VACON_MAIL_DOMAIN`으로 바꿀 수 있습니다.
- 로그인 정보는 기본적으로 저장하지 않습니다. 저장을 선택하면 이 PC의 Windows 사용자 계정 DPAPI로 암호화해 `%LOCALAPPDATA%\VACON\groupware_credentials.bin`에 보관하며, VACON 화면에서 삭제할 수 있습니다(Windows 전용).
- 메일은 VACON DB에 저장하지 않고 현재 Streamlit 세션에만 둡니다. ALIRA 메일 브리핑 작성 시 제목·발신자·본문(메일당 최대 3,000자)이 `ALIRA_API_BASE`의 사내 서버로 전송됩니다. 외부 AI API에는 보내지 않습니다.
- 로그인 정보 암호화 저장은 `services/groupware_mail.py`가 담당합니다.
- ALIRA 연결이 실패하면 로컬 규칙 기반 참고 요약을 표시합니다.

### 구글 시트 연동 (데이터 관리 > 시트 연동)
#### 과거 버전 업무 로그 자동 수집
- 기존 업무 로그는 시트 링크를 넣거나 두 탭이 포함된 `.xlsx`를 올리고 `ALIRA로 시트 전체 분석 및 업무 로그 만들기`를 누르면 가져옵니다. 대상 탭은 `2. Dynamic_Verification`, `3. Req_Creation_WBS`로 고정하며 버전은 T0700까지로 제한합니다.
- 탭명에서 요구사양서 작성/동적 검증을 판별하고 ALIRA가 헤더 행과 VACON 열 매핑을 제안합니다. 모든 원본 행은 기존 `work_logs` 구조로 파싱되며, 업무 지표 값은 임의로 생성하지 않습니다. 확인 미리보기 후 기존 검증 업무 로그 저장 경로로 반영합니다.
- 비공개 Google Sheets는 Google OAuth Desktop client JSON을 최초 한 번 등록하고, 사용할 Google 계정으로 읽기 권한을 승인해야 합니다. 토큰과 클라이언트 설정은 Windows DPAPI로 암호화해 이 PC의 `%LOCALAPPDATA%\VACON`에 저장합니다. Google Cloud에서 Sheets API를 활성화한 OAuth Desktop 앱 자격 증명이 필요합니다.
- 같은 시트 탭의 기존 기록은 출처와 행 번호를 기준으로 갱신하고 새 행은 추가합니다. T0700 이후 및 버전이 확인되지 않는 행은 자동 수집에서 제외합니다.

탭별 CSV(`/export?format=csv&gid=…`)를 읽어 업무·마감일을 갱신합니다. 열 이름을 코드에 고정하지 않고 **화면에서 열 매핑**을 지정·저장합니다.
1. 시트 공유를 "링크가 있는 모든 사용자 - 뷰어"로 설정하고 주소를 저장합니다.
2. 탭을 추가합니다: 탭 이름, **gid**(해당 탭을 열었을 때 주소 끝 `#gid=` 뒤 숫자), 역할(업무 목록/일정), 헤더 행 번호.
3. "열 목록 불러오기" → 업무명·담당자·상태·진행률·마감일 등을 드롭다운으로 매핑 → 저장.
4. "시트에서 새로고침(미리보기)" → 추가/변경/사라짐 건수와 변경 내용을 확인 → "반영".
- 시트 값이 원천인 항목(담당자·상태·진행률·마감일·남은 작업·주의사항)만 갱신합니다. **대체 담당자·중요도·예상 부담은 덮어쓰지 않습니다.**
- 시트의 빈 칸은 기존 값을 지우지 않으며, 해석할 수 없는 값(상태·날짜·진행률)은 추측하지 않고 경고로 표시하고 건너뜁니다.
- 시트에서 사라진 업무는 자동 삭제하지 않고 목록으로만 알려줍니다.
- 시트의 열 이름이 바뀌어 매핑이 깨지면 반영하지 않고 알려줍니다. 업무는 업무명(공백·대소문자 무시)으로 식별하므로 시트에서 이름을 바꾸면 새 업무로 보입니다.
- 직접 연결이 막힌 환경에서는 탭을 CSV로 내려받아 같은 화면에서 업로드하면 동일하게 처리됩니다.
- 새 업무의 필수 역량·기본 중요도는 탭 설정에서 지정합니다(중요도를 '미입력'으로 두면 위험도가 '데이터 부족'으로 표시되어 입력을 유도).

### 버전 데이터 경로
- T0800 미만의 숫자형 T 버전은 기존 Google Sheets 로그로 조회합니다. T0800 이상은 VACON 내부 DB에서 관리하며 시트 동기화 시 해당 행만 제외합니다.
- 내부 버전은 `version_projects`와 서브시스템별 물량 테이블을 사용합니다. 요구사양서 작성 기록(`spec_work_logs`)과 동적 검증 기록(`version_dynamic_work_logs`)은 서로 다른 테이블에 저장됩니다. 기존 Sheets 연동의 `req_work_logs`/`dynamic_work_logs` 테이블은 그대로 보존합니다.
- `(PM) 검증 일정 관리`에서 T0800 이상 버전과 마감일, 서브시스템별 목표를 등록합니다. 담당자 실적은 `검증 업무 기록`에서 기록하고 `검증 업무 로그`에서 통합 조회합니다.
- 실적 입력과 PM 배정 추천 대상은 김재강·주해원·황지원·이혜윤으로 제한합니다. 전체 사원 정보와 과거 기록은 보존합니다.
- 담당자 배분은 지정 인력의 업무량, 휴가, 역량, 난이도와 과거 버전의 서브시스템 담당 이력을 기준으로 추천합니다. 같은 서브시스템의 연속 배정을 낮추고 작성·검증 담당자 분리를 우선 고려하며, 추천은 PM 승인 후 배정으로 저장됩니다. LLM 설명은 별도 동의가 있을 때만 팀원명·배정 요약을 사내 LLM 서버로 전송합니다.

### 단위 테스트 업무 로그 (검증 업무 로그, 데이터 관리 > 시트 연동)
단위 검증 담당자 **김재강·주해원·황지원·이혜윤**의 두 업무 — **동적 검증**, **요구사양서 작성** — 실적을 통합 조회합니다. 과거 버전은 기존 Google Sheets를 읽기 전용 원본으로 사용하고, T0800 이상은 VACON 내부 DB를 사용합니다.
- **열 지정(열 문자 기준, 기본값 설정됨):** 동적 검증(`2. Dynamic_Verification`) = 날짜 A · 담당자 B · 버전 C · 업무 구분 D · 완료 Req I · 완료 Func L · 실행 TC O / 요구사양서 작성(`3. Req_Creation_WBS`) = 날짜 A · 담당자 B · 버전 C · 업무 구분 D · 완료 일감 G. 서브시스템은 헤더명으로 열을 제안하며, 탭마다 **gid**만 입력하면 됩니다.
- **해석 규칙(가정):** 시트 한 행 = 한 사람의 하루 기록(같은 날 여러 행은 합산), 숫자 칸은 그날의 건수입니다. 숫자가 아닌 텍스트 칸은 쉼표·줄바꿈 기준 항목 개수로 세고 미리보기에서 알려줍니다. 해석할 수 없는 날짜·이름의 행은 건너뛰고 사유를 표시합니다.
- **날짜 형식:** `2026-10-19`, `2026. 10. 19.`, `2026년 10월 19일`, `26.10.19`, `10/19/2026`, `20261019`, 요일·시간이 붙은 값(`10/19(월)`, `2026-10-19 09:30`), 시트 일련번호, 연도가 없는 `10/19`·`10월 19일`을 읽습니다. 연도가 없으면 오늘 기준 가장 가까운 과거로 추정하며(탭 설정에서 연도 직접 지정 가능), 읽지 못한 값은 **예시와 함께 화면에 표시**합니다.
- **진단 도구:** "열 목록 불러오기"를 누르면 앱이 실제로 읽은 시트 상단(행 번호·열 문자 포함)을 보여주고, 제목 행이 다른 위치에 있으면 행 번호를 추정해 알려줍니다. 날짜·담당자가 병합 셀이면 "병합 셀 대응"을 켜세요.
- **시트 구조 변경 감지:** 저장한 열 제목과 현재 시트의 해당 열 제목이 다르면 반영하지 않고 알립니다. 반영은 미리보기(팀원별 합계) 확인 후 **탭 단위로 교체**(누적 아님)되므로 시트에서 수정·삭제한 내용도 그대로 따라갑니다.
- **집계 기준:** 최신 버전이 위에 오도록 정렬하며 버전과 서브시스템을 선택합니다. 선택한 버전의 전체 로그 또는 해당 서브시스템 로그만 집계합니다. 서브시스템 열이 매핑되지 않은 과거 로그는 `서브시스템 미입력`으로 분류됩니다.
- **분석:** 팀원·업무별 처리량(근무일 기준 일평균, 주말·종일 휴가 제외; 로그가 없으면 0이 아니라 '-'), **휴가 영향 예측**(최근 일평균 × 휴가 근무일 = 예상 처리 공백, 나머지 단위 테스트 인원이 처리량 비례로 나눠 맡을 때의 추가 부담과 '평소 대비 +n%'), 단위 테스트 인력 가용 현황.
- **단위 테스트 인원 전용 규칙:** 필수 역량에 `단위테스트`가 들어간 업무는 담당자·대체 담당자가 단위 테스트 인원이어야 합니다(입력 화면·시트 동기화에서 검증). 대체 담당자 추천은 필수 역량을 **모두** 가진 사람만 후보로 올립니다(필수 역량은 쉼표로 여러 개 지정: `단위테스트, 요구사양서 작성`). 위험 분석에는 '역량 보유자 다수 부재' 항목이 추가되었습니다.
- 단위 검증 인수인계 문서는 과거 버전을 나열하지 않고 현재 진행 버전의 본인 실적과 팀 전체 잔여량을 구분합니다. 개인별 대체 업무는 선택한 휴가와 기간이 맞고 대체 담당자 페이지에서 PM 승인 저장된 내용만 표시합니다. 승인안이 없으면 배정된 것으로 간주하지 않습니다.
- 예측은 과거 평균에 근거한 참고값이며, 마감 달성 가능 여부는 남은 물량(전체 Req/TC 등) 정보가 있어야 판단할 수 있습니다.

### 검증 일정 및 업무 기록 (PM 검증 일정 관리 · 검증 업무 기록)
- T0800 이상 버전만 VACON 내부 DB에서 관리합니다. PM은 버전, 단계별 마감일, 서브시스템별 요구사양서 작성 일감 및 검증 대상 함수·요구사양서 수를 등록합니다.
- 요구사양서 작성 기록과 동적 검증 기록은 별도 테이블에 저장·집계합니다. 작성 완료 일감과 신규·수정·삭제 요구사양서 수, 검증 완료 함수·요구사양서와 결함·TC 수를 독립적으로 관리합니다.
- 담당자·업무 날짜 선택 시 과거 버전 기록, 현재 계획, 업무량과 부재를 고려해 서브시스템을 추천합니다. 추천에는 반복 담당·업무 순환 권장과 작성·검증 분리 근거가 표시되며, 최종 배정은 PM이 검토합니다.
- PM 배정 추천은 승인 전까지 저장되지 않습니다. 추천 근거 설명을 LLM으로 요청할 때만 팀원명과 배정 요약이 사내 LLM 서버로 전송됩니다.
- 대체 담당자 화면을 열면 선택된 휴가·업무와 VACON 계산 후보의 가용량, 업무 이력, 배정량 근거를 사내 ALIRA 서버에 보내 순위와 사유를 자동으로 받습니다. 결과는 같은 데이터 상태에서 재사용합니다. 배정 수량과 완료 예측은 VACON 계산값을 유지하며, ALIRA가 배정을 저장하지 않습니다. 최종 저장은 기존 PM 승인 후에만 가능합니다.

### AI Agent (💬 AI 비서)
- `ALIRA_API_BASE`·`ALIRA_MODEL`이 설정되어 있으면 모든 질문을 **항상 ALIRA AI Agent**가 처리합니다(별도 토글·예시 질문 버튼 없음). 사내 LLM 서버(OpenAI 호환 `/v1/chat/completions`)의 Tool Calling으로 필요한 VACON 조회를 최대 6회 순서대로 수행합니다.
- 도구는 휴가 조회, 버전/진행률 조회, 업무량 계산, 위험 분석, 대체 담당자 추천, 인수인계 초안 생성입니다. 기존 DB·서비스 함수를 사용하며 SQL/Python 임의 실행과 데이터 변경 도구는 제공하지 않습니다. 추천 지정, 휴가 변경, 일정 변경, 문서 저장/전송은 Agent가 실행하지 않습니다.
- 질문마다 **VACON 기본 데이터 스냅샷**(`services/snapshot.py`)을 시스템 프롬프트에 함께 넣습니다. 팀원·역할·부하·역량, 업무(담당·대체·상태·진행률·마감 D-day·남은 작업·메모 120자), 최근 30일 이후 휴가, 버전 일정·담당·완료 수, 최근 28일 업무 로그의 담당자·유형별 합계이며 날짜에는 요일을 붙입니다(최대 24,000자, 연락처 제외). 그래서 "휴가랑 마감이 겹치는 사람?"처럼 여러 데이터를 엮는 질문은 도구 없이 직접 분석하고, 위험 점수·대체자 추천·작업량·로그 상세는 도구로 정확히 계산합니다. LLM이 직접 비교·계산한 내용은 틀릴 수 있으니 중요한 판단은 해당 화면에서 확인하세요.
- Agent는 질문, 기본 데이터 스냅샷, 도구가 반환한 데이터를 사내 LLM 서버에 전송합니다. AI 비서 화면 상단에 전송 사실을 안내합니다. 실행 기록에는 도구명·성공 여부·소요 시간만 남습니다.
- 사용하려면 `ALIRA_API_BASE`와 `ALIRA_MODEL`을 환경 변수로 설정하세요(추가 패키지 불필요). 서버는 vLLM의 tool calling(`--enable-auto-tool-choice`)이 켜져 있어야 합니다. AI 비서 화면에서 **ALIRA 연결 확인**으로 서버와 모델 등록 상태를 점검할 수 있습니다. 응답 속도를 위해 thinking 모드는 기본으로 끕니다(`VACON_LLM_THINKING=1`로 사용).
- 📝 인수인계 화면에서 문서 생성을 누르면 ALIRA가 단위 검증 담당자의 현재 진행 버전 계획·배정·실적과 휴가 기간 예정 일정, 실제 기록된 특이사항을 바탕으로 작성합니다. 요구사양서 작성과 동적 검증 지표, 개인 완료량과 팀 잔여량, 예정 일정과 실제 실적을 구분하며, 과거 버전·미승인 재분배안·기록되지 않은 사실은 문서에 추가하지 않습니다. 대체 담당자 배정은 대체 담당자 페이지에서 휴가 기간에 대해 승인 저장된 내용만 표시합니다. ALIRA 미설정 또는 호출 실패 시 VACON 템플릿을 제공합니다. 인수인계 작성 중에는 진행 상태를 표시하며 생성 결과는 세션에서 확인·수정하고 Markdown·TXT로 저장할 수 있습니다.

## 제한 사항
- 기존 위험 분석·휴가 영향 예측은 회사 공휴일을 관리하지 않으며 주말만 제외합니다. 버전별 업무량 추천도 주말과 담당자 휴가를 반영합니다.
- 반차는 기본적으로 '부재'로 보지 않고 가용 인원에서 0.5명으로 계산합니다.
- 업무량·예상 업무 부담은 사용자가 입력한 값을 그대로 사용하며 실제 업무 시스템과 연동하지 않습니다.
- 사용자 인증/권한, 다중 사용자 동시 편집은 지원하지 않습니다(로컬 SQLite 단일 사용자 기준).
- 구글 시트 연동은 앱에서 '새로고침'을 누를 때 읽어 오는 방식이며 실시간 자동 반영은 아닙니다. 공유 설정이 막힌 시트는 CSV 업로드를 사용합니다.
- 메일 연동은 사내망에서 회사 메일 계정(IMAP)이 필요합니다. 로그인 정보 저장은 Windows에서만 지원합니다. 메일은 사용자가 가져오기를 눌렀을 때만 읽고 세션 종료 시 메모리에서 사라집니다. 메일 요약은 사내 ALIRA 서버를 사용합니다.
- MBTI는 팀원 정보로 저장·표시만 하며 위험도 계산이나 대체 담당자 추천에는 사용하지 않습니다.
- 기존 `vacon.db`는 실행 시 `mbti` 컬럼이 자동 추가되어 데이터가 유지됩니다.
- LLM 요약은 선택 기능이며, 규칙 기반 답변을 문장으로 다듬는 용도로만 사용합니다.
